I just rebuilt my website in a day, and I couldn't have done it without Claude. I'm still not sure how I feel about that. I love my job, and I want to be proud of the fruit of my labour, which is hard when Claude did most of the grunt work. I've even told my manager that I feel conflicted about how much AI is being pushed on us, because I want to keep sharpening my own skills instead of letting them quietly rust away. This is a quick read about how I'm making peace with that, and why I think the answer isn't "use it" or "refuse it".

Yes, I see the irony in what you're about to read. This post was written in a file Claude helped me finish.

## The new site

For a long time this website was a single HTML page. It did the job, but it was never going to grow into what I wanted: a proper home for my projects, my resume and, well, posts like this one.

So I rebuilt it in [Next.js](https://nextjs.org). You can see the result on the [projects page](/projects/) or browse the [source on GitHub](https://github.com/MichelGeorgesNajarian/mgnajarian.com). The plan was drawn up with Opus, using my input and the initial setup I had put together. From there, the brunt of the work was done by Claude: the pages, the components, the blog setup and the SEO fixes. I reviewed, steered and corrected, but I won't pretend I typed most of it.

And here's the honest part: I wouldn't have been able to do all of this myself in the same day. Not even close.

## We've been here before

When I think about it, this isn't the first time the ground has shifted under software engineers. There was a time when writing assembly was simply what programming was. Moving to higher-level languages must have felt like cheating to some people. You no longer knew exactly what the machine was doing, and you were trusting a compiler to do the part you used to be proud of getting right.

Today, almost nobody writes assembly for everyday work, and nobody considers a C, Java or Python developer less of an engineer for it. The abstraction moved up, and the craft moved with it. The job was never about the instructions. It was about solving the problem.

<Callout title="The job was never the instructions">
  Assembly to high-level languages, and now maybe prompts to code: each step
  trades some control for leverage. The craft is deciding what to build and
  whether it's right.
</Callout>

I can't say for sure that AI is the same kind of shift, but it rhymes.

## Still conflicted

That doesn't make the discomfort go away. I still worry about:

- **Understanding.** If I don't write it, do I really know how it works? I try to read everything Claude produces, because the code ships under my name.
- **Pride.** It feels different to look at something and think "I built that" versus "I directed that".
- **Skills.** Muscles you don't use get weaker. I'd like to keep mine.

I don't think those worries are silly, and I don't think they should be dismissed. But I also don't think they're a good reason to refuse the best tools available to me, especially when the people and companies around me are already using them.

## Where I've landed (for now)

Software engineering has always been an ever-changing discipline, and keeping up starts with yourself. Using every tool at our disposal is part of the job in today's day and age. The trick, I think, is to stay in the driver's seat: have opinions, review the output, understand what ships, and keep doing the hard thinking myself. Let the tools take on the grunt work, not the judgment.

I'm not fully at peace with it, and I'm not sure I ever will be. But this site exists, today, because I leaned on these tools, and I'm happy with where it ended up.

If you're in the same boat, struggling with how things are now, I hope you find your way through it. It's okay to be conflicted. Just don't let the conflict keep you standing still while everything else moves.
